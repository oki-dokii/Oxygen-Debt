# Oxygen Debt design

## What is implemented

The Python CLI parses KIR, validates the requested machine, and runs local simplification, common subexpression elimination, load reuse, signed division simplification, branch folding, jump threading, unreachable-block removal, loop hoisting, dead-code removal, copy elision, instruction fusion, and register reuse. It also lowers proven polynomial summations, reuses proved memory values across loop iterations, schedules bounded blocks, and exhaustively specializes pure functions with a proven finite input domain. It additionally proves fixed-trip bit maps, offers natural-loop LICM and additive nest collapse, and compares a bounded whole-function portfolio, including proved deferral of checksum remainders. A supplied profile guides layout and bounded candidate timing weights. With no edits, the CLI emits the original bytes. The parser, machine loader, and fused-feature validation in `src/kirlib.py`, and the interpreter and timing model in `src/kiln.py`, are adapted from the permitted official COMP10 starter kit at commit `d23ac1d`. Tests use an independent, unmodified external checkout. [Upstream source](https://github.com/rudra-shroff06/LLH-26/blob/d23ac1d865df4cdacf7ad8e9fff3e1d560761c46/Compilers/COMP10/kirlib.py)

## Pass order

The CLI checks the input and machine, computes signed entry ranges for constants, arithmetic, and memory proofs, then walks forward to simplify each block. It threads jumps, removes unreachable blocks and overwritten stores, and converts simple conditional assignments into selects. It then hoists loop invariants before running backward liveness. Fixed-trip bit synthesis and bounded summation lowering follow liveness; a nested-loop candidate also repeats additive-loop collapse and adjacent-block cleanup. Copy elision and fusion run on retained instructions after liveness converges. Proven summations become straight-line formulas, followed by simplification, reachability, and liveness cleanup. A checksum candidate can defer a common positive modulus, then recomputes ranges before cleanup. Register reuse renames local values before layout. A second jump pass uses that layout to bypass blocks exposed by dead-code removal. Adjacent straight-line blocks can then merge. Proven cross-iteration memory reuse runs after allocation, before bounded scheduling and loop doubling. The CLI attempts finite-domain specialization. For multi-block functions with 5–500 input instructions, it also tries up to four bounded alternative pass combinations, then chooses among the original and generated candidates using deterministic timing cases. ## Each pass

**Local simplification.** Track the value a register holds and which other registers still hold that value. Resolve sources before updating the destination, then remove that register from its former value's holders on overwrite. Seed each block only with entry ranges that describe a single value. Use KIR's 32-bit wraparound, signed comparison, and masked shifts when folding. The forward scan and output edits take expected linear time and space in the input size.

**Common subexpression elimination.** Key pure arithmetic, comparisons, and selects by their opcode and operand values. Normalize operand order for commutative operations. Reuse an expression only while a register still holds its result. Table lookups take expected constant time per instruction.

**Load reuse.** Record the value read or written at each address within a block. A store to a literal address invalidates facts for all dynamic addresses and updates its own slot. A dynamic store invalidates both tables before recording its value. Reuse a literal or a register that still holds the recorded value. Reaching the second access proves that the earlier access to that address succeeded, so the removed load cannot introduce a new trap. The two tables take linear total work to maintain because each cleared entry must first have been inserted.

**Signed ranges and division.** Propagate signed lower and upper bounds through the control-flow graph. Join incoming ranges by taking their enclosing interval. An exact branch condition sends facts only to its selected edge. If incoming facts later grow, revisit the block so newly possible edges receive facts. A signed less-than feeding a branch can narrow its operands, including when a comparison with zero negates the result. The comparison sequence must preserve both operands. For exact values, use the same wrapping arithmetic as local folding. For wider ranges, add and subtract yield an unknown range when they can wrap. Expanding bounds on repeated backward edges widen toward the signed limits. A budget of 500,000 work units bounds the propagation and falls back to facts within each block. Fold exact operands, simplify divisors of magnitude one, and use shifts or masks for proven nonnegative dividends and suitable powers of two. Every division rewrite requires an exact nonzero divisor.

**Memory cleanup.** Prove an ordinary address lies wholly in the range 0 through 4095. Backward liveness can drop an unused load with that proof. To remove an overwritten store, match address values within a block, including identical additions of unchanged operands, and require a later store to the same address before any ordinary read or volatile operation. Mark blocks with a possible trap and walk backward through their predecessors. Only blocks outside that set can lose overwritten stores. Both the graph walk and the scan of stores take expected linear time.

**Control flow.** Replace a branch with a jump if its condition is known within the block or both targets are identical. For a condition defined by an equality with zero, branch on the tested value and swap targets if a register still holds that value. Prefer the register read by the comparison. When spills can cost cycles, skip the rewrite if either register is read in multiple blocks. Liveness removes the comparison if its result is unused. Resolve each chain of jump-only blocks to its endpoint, caching the result for every hop. Paths that enter a jump cycle keep their original edges. Redirect branches and jumps to resolved endpoints, then follow the resulting edges from the original entry and delete unvisited labels and instructions. The walks are iterative and take linear time in the number of blocks and edges, plus the time to mark removed instructions.

**Late jump cleanup.** After layout and register reuse, bypass newly empty blocks when the old path takes a jump or the entire fallthrough chain can be removed. Keep shared fallthrough chains when bypassing them could add a taken jump. A jump to a return-only block can become the same return directly. Recheck reachability after these edits. The same iterative chain lookup bounds the work.

**Block merging.** Remove a jump and the target label when the target has one incoming edge and immediately follows the source both in source order and in the selected layout. Concatenate their instruction lists while preserving instruction order and allocated register names. Running this after allocation avoids changes in spill behavior from enlarging an allocation region. Each block is visited once, and each retained instruction is appended once.

**Conditional assignments.** Recognize a branch whose two arms each assign the same register with one copy or constant, then jump to the same block. Each arm must have exactly one incoming edge. Emit a select before an unconditional jump to their common successor, and remove the unreachable arms. KIR reads the condition and sources before writing the destination, so the destination can also be the original condition register. The scan takes linear time in the number of blocks and edges.

**Loop hoisting.** Find a branch header with a single body that jumps back and an existing block that jumps to the header from outside the loop. Move a group of pure instructions into that entry block if their operands come from outside the loop or from earlier instructions in the same group. Each moved instruction must write its destination exactly once in the loop. All reads of that destination must follow its definition in the body, so an entry that skips the loop can compute the value without affecting later reads. Require at least two instructions and one result read by the remaining loop body to limit register pressure. The graph and operand scans take expected linear time.

**Loop doubling.** Find a comparison and branch header placed immediately before its sole-entry body, which ends in a jump back to the header. Keep the header for the first test. Replace the back jump with a copy of the comparison and branch that can fall through into a second body copy. The second copy branches back to the first or exits. Each dynamic iteration runs the same body operations and one condition check in the same order. The pass skips volatile bodies and applies to bodies of up to 12 instructions, including the original jump. When the machine charges for register spills or instruction cache misses, require the loop's registers and the expanded program to fit their respective limits. The pass and emission take linear time in the input and output size.

**Dead-code removal.** Compute each block's live-out set from the union of its successors' live-in sets, then scan backward. Drop a pure instruction only if its destination is dead. Revisit predecessors when live-in changes. The cost grows with the total size of blocks and live sets visited. The worklist has a fixed budget of two million work units based on instruction visits, predecessor edges, and live-set entries. If the budget runs out, use dead-code removal only in blocks with no successors, where live-out is known to be empty.

**Copy elision and instruction fusion.** Scan retained instructions backward with the current live set. A pure computation followed by a copy can write directly to the copy's destination if the temporary is dead after the copy. Fuse an adjacent `mul` or constant-count `shl` into `add` only when the add reads the temporary once and its old value is dead after the add. Multiplication by a power of two is equivalent to a left shift modulo 2³², so that pair can also use `addsh`. Both rewrites read the producer's original operands before writing the final destination, including when the producer reads that register. The scan takes expected linear time plus the cost of forming live-out sets. [Research references](docs/RESEARCH.md)

**Register reuse.** Reserve parameters, registers live at block boundaries, and every register used by volatile I/O. In each block, walk backward to locate the last read of each remaining definition, then assign those definitions names from a shared pool. A name becomes available after its last read, including before the same instruction writes its result. Each read therefore sees the same definition as before. Sorting the names and allocating with a heap take O((N + R) log R) time for N instructions and R register names.

**Block layout.** Sort surviving edges by profile weight and join chains at their tails and heads, keeping the entry first. Compare the proposed order with the current one using estimated taken-branch and instruction-cache penalties. Sorting costs O(E log E) for E candidate edges, and scoring scans the retained blocks and instructions. Moving labeled blocks preserves every explicit transfer. [Profile-guided code positioning](https://doi.org/10.1145/93542.93550)

**Polynomial summations.** Recognize a separate preheader, a two-instruction comparison/branch header, a sole-entry body returning to the header, and a return-only exit. Signed ranges must prove an invariant bound `0 <= n <= 255` and initial index zero. Symbolically execute the body over polynomials in the index and accumulator modulo 2³², of total degree at most three. Require final index `i + 1` and accumulator `a + p(i)`; other loop-written registers start unknown. Reject memory, volatile I/O, unsupported operations, and additional carried state that affects the recurrence. Replace the loop by `S0=n`, `S1=n(n-1)/2`, `S2=n(n-1)(2n-1)/6`, and `S3=S1²`, weighted by the polynomial coefficients and added to the original accumulator. The bound makes the products preceding division fit signed 32 bits. Exact halving uses logical shift. When cheaper, divide `S1*(2n-1)` by three by multiplying with `0xAAAAAAAB`, the inverse of three modulo 2³²; exact divisibility and bounded arithmetic justify this substitution. Zero-trip inputs are included. A final positive modulus is supported only when the initial accumulator is already reduced, every increment is nonnegative, and the entire unmodded sum fits signed 32 bits. Preserve all preheader effects. The structural and symbolic scans are O(n), plus the existing bounded range analysis. Scan at most 100,000 retained instructions and lower at most one loop per invocation.

**Cross-iteration memory reuse.** Recognize a separate preheader, invariant header computations followed by a signed comparison/branch, and a sole-entry body that jumps back. Require a known nonnegative initial index, an invariant bound through 4096, and a proved positive constant stride through 4096. Symbolically track addresses as `a*i+b` modulo 2³²; loop-written locals begin unknown, so initial values cannot masquerade as carried invariants. A later load or store at `a*i+b+a*stride` can supply a load at `a*i+b` on the next iteration. Choose the last matching access, reject any possibly aliasing store before the replaced current load or after its supplier, and capture the supplier's value immediately after that access. Equal coefficients with different offsets are disjoint modulo 2³²; other disjointness needs nonwrapping interval separation. Preload a fresh carry register at the exact initial address only when it is in 0–4095. The preload is harmless even if the loop is skipped. Replace the original load with a copy and preserve every original store, possible trap and other operation. Skip volatile bodies. Evaluate up to four single-load alternatives and one two-load alternative on structural two- and eight-iteration timing paths; require neither path to slow. Skip candidates that add spills or instruction-cache overflow, and preserve every existing loop-doubling opportunity. Limit the function to 5,000 instructions, each body to 128 instructions, and optional modeling work to 200,000 units. With the fixed body cap, address/supplier scans are O(n × 128), plus bounded range analysis and timing work. The timing paths are profitability estimates; the affine and alias checks establish semantic validity.

**Instruction scheduling.** For blocks with 3–32 nonterminating instructions, form register read-after-write, write-after-read, and write-after-write edges. Chain ordinary loads, stores, division, and remainder in their original order so aliasing and traps cannot move past each other. Skip volatile blocks. Greedily select ready operations using earliest issue time, critical-path height, and original index as a deterministic tie-breaker. Keep the terminator last. Compare candidate timing with the permitted model on repeated blocks and adjacent control-flow paths; require every modeled path to tie or improve, with at least one improvement. Skip programs above 5,000 instructions. For programs that can spill, additionally cover all bounded incoming and outgoing contexts through three edges, plus simple cycles of up to six blocks repeated three times. Skip a candidate if branching would exceed eight incoming or outgoing contexts, eight cycles, 128 combined paths, or 512 instructions per added path. A deterministic 200,000-unit budget charges both original and candidate cost-model setup and instruction visits across the function. This captures more register-residency histories without assuming that short isolated blocks represent an entire loop. No instructions are added or removed. With block size capped at 32, dependency construction is bounded per block; copying and scoring whole-program timing arrays can take O(n²) overall, so the 5,000-instruction cap limits this work. The timing paths are profitability estimates, not semantic proofs or a guarantee of speed on every input.

**Finite-domain specialization.** Require one or two read parameters, no memory operations, volatile I/O, or explicit traps, and at most 5,000 instructions. Every read of each original parameter in the entry block must be an `and` with a literal until it is overwritten; if it remains unmodified, reject later reads outside that block. The combined register/bit positions across those masks must total at most twelve bits. Therefore the entire execution depends only on those bits; every other initial register is zero, and any remaining parameters are unused. Enumerate all 2^k representatives across both input words, including high and noncontiguous bits. Abort if any execution traps, fails to return within 20,000 steps, or exhausts a two-million-step total budget. Generate an interned decision tree and, when low input bits and output width permit, a table packed into 32-bit literals and selected by shifts. Neither candidate uses observable memory. Verify each candidate on every representative and compare exact products of cycle counts, equivalent to comparing geometric means over this complete domain. Emit only a strict improvement. Evaluation visits at most two million original instructions; setup and cost modeling additionally take O(2^k × n) for k <= 12, with bounded decision-tree construction and exact integer score products. All results are computed from the current input source during compilation; there are no benchmark names, hashes, cached solutions, or input-file reads. A separate two-million-unit timing budget and 4,096-instruction candidate cap bound wider-domain scoring. This is exhaustive reasoning over a proven quotient of all inputs, not testing a sample of possible inputs.

**Fixed-trip bit synthesis.** For a pure region of at most 96 instructions and 16 blocks, prove a constant initial counter, immutable constant bound through 32, and exactly one increment on every iteration. A population-sum recognizer checks the word recurrence `a += (x >> i) & 1`, with invariant x, then emits masked SWAR counts. Pair fields of width 1, 2 and 4 count disjoint source bits; byte multiplication gathers the total without byte overflow. Otherwise symbolically execute each fixed iteration over GF(2): every output bit is an XOR of input bits and a constant. Constant shifts/masks and XOR preserve that form. OR requires a zero/one/identical operand in each bit. A conditional can merge only when its condition is a single bit and each arm difference is constant. Unknown carry arithmetic, nonlinear products, effects and unsupported control flow reject. Liveness at the header prevents dead branch temporaries from requiring spurious merges. Reflection matrices use parallel word swaps; other maps use grouped shifts and masked input-bit columns. All externally read loop-written registers are restored, including counter/condition values. Compute outputs before overwriting original inputs. Bound symbolic visits to 8,192, input basis bits to 256 and emitted operations to 256. With these fixed caps the scan is O(n), plus bounded range/liveness work. No function names or CRC polynomials are built into the recognizer.

**Nested hoisting and additive collapse.** A separate candidate computes dominators and natural loops, visits outer loops first, and moves at most 16 pure invariants per loop into a sole preheader. Require one static definition, dominance of every use, no self-read, and no use outside that loop; the latter protects zero-trip executions. The search is capped at 256 blocks/2,000 instructions. It can then collapse up to four one-body additive loops. Symbolic word-linear forms must prove `i'=i+1` and `a'=a+c*i+sum(k_j*x_j)+k0`, with invariant x_j, initial i=0 and bound n in 0–255. Emit `a+n*sum(k_j*x_j)+c*n*(n-1)/2+k0*n`; the bounded even product makes halving exact. Require every other externally read loop-written value to be just the final counter or condition, and restore those. Reject effects, signed remainder and nonlinear recurrences. Constant folding and block merging expose a parent loop for another proof. Ring arithmetic preserves wrapping for negative coefficients and arbitrary initial accumulators. Dominator solving is bounded; linear scans plus the existing analysis budgets bound collapse work.

**Deferred checksum remainders.** For a sole-entry counting body of up to 128 instructions, prove an initial index of zero, an immutable bound in 0–1,024, and identical untainted `i+1` updates. The normal exit must have only the header as predecessor. The body can contain ordinary loads and pure operations, but no stores, volatile I/O, division or other control flow. All remainder divisors must be the same proved positive constant. Simulate original reduced intervals and candidate unreduced intervals through every iteration up to the maximum bound. An untainted value is numerically identical; a tainted value is congruent modulo M. Copies preserve that relation. If an unreduced candidate is already in 0–M−1, congruence proves equality and clears its taint; redundant remainders can disappear without exit normalization. Affected addition, multiplication, fused arithmetic and left shifts require nonnegative operands and mathematical (unwrapped) results no larger than INT_MAX. Shifts require an untainted shift amount. Conditional selection requires an untainted predicate and bounded nonnegative arms. Other affected operations reject. Mathematical bounds deliberately bypass 32-bit constant folding: a wrapped product can look positive again and is not a no-wrap proof. Loads must use untainted addresses and stay in place. A load trap observes identical memory/volatile history because the body has no writes or I/O; differing register state is not observable on a trap.

Replace body remainders with copies and normalize affected externally read registers on the unique normal exit. Require their original values to be in 0–M−1 at every possible iteration exit, including exits before those registers became tainted, and require initial values already reduced for the zero-trip case. This rejects live raw numerators and late-taint hazards. Recompute range facts for the new graph; old reduced-state ranges must not seed unreduced arithmetic. The proof runs only up to 2,000 retained instructions with a 200,000-instruction-visit budget; body/iteration caps bound simulation to O(n × 1,024). It offers one loop rewrite as an extra portfolio candidate; the old optimized trajectories and original input remain available.

**Whole-function candidates.** Keep the unchanged source as a fallback. In addition to the standard pipeline and its finite specialization, try no unrolling; no rolling reuse/scheduling/allocation; nested hoisting plus additive collapse; and checksum-remainder deferral when the source contains remainder operations. Generate no more than these four alternatives for functions up to 500 instructions. Sixteen fixed edge/LCG argument and memory cases rank candidates by exact integer products of cycles. Original executions have a 100,000-step budget (20,000 per case); candidate executions share 500,000 steps. Skip reference runs that exceed their step limit, require at least two finished cases, and reject a candidate on any observed behavior mismatch. These self-checks are safeguards, not equivalence proofs: every transformation still requires its structural proof. The original remains selected without a complete strict improvement. Profiles can double the weight of at most four cases nearest their valid original CFG edge counts; all other cases retain weight one. No clock, filename, benchmark input or unfixed randomness influences selection. Budget exhaustion retains only a fully evaluated earlier winner.

## The machine

The CLI checks that the original program uses only supported fused operations. It simplifies a multiplication to a constant or copy when `lat_alu` is at most `lat_mul` and applies a similar check against `lat_load` for load reuse. When spilling can cost more than loading, it keeps literal-address and self-overwriting loads that would gain a register read. When spills can cost cycles, copy propagation keeps original register operands that are read in multiple blocks, copy elision removes intermediate writes, and reuse of cheap expressions stays within uninterrupted spans of pure instructions. Fusion requires machine support and compares the fused latency with the sum of the two original latencies. When both fused forms apply, it chooses `addsh` if it has lower latency. Register reuse runs when the remaining names exceed the machine's register count and spilling has a cost. If the new program would still spill, it estimates reloads on repeated one- and two-block cycles and restores the original names in those blocks when the estimate rises. ## Keeping the behaviour

The replacements compute identical bits in the same destination or use a register that holds the same value. A folded branch jumps to the target the original would take. Threading skips only unconditional jumps, which have no register, memory, or volatile effects. Memory cleanup preserves the store sequence on trapping paths and keeps volatile operations in their original order with their original operands. Volatile accesses use a separate device state, so they preserve ordinary memory facts. The official interpreter checks the ending, volatile log, and data memory. [Software requirements](docs/SRS.md)

## Profiles

Layout and bounded candidate ranking use profile counts. Candidate weighting is described above; nonexistent edges are ignored and hints never change transformation legality. Early jump threading carries the count of a redirected edge to its new target. Layout ignores malformed entries and counts for edges absent from the optimized graph. It gives existing fallthrough edges a small bias to retain them when counts are close or missing. Block visit estimates use the larger of incoming and outgoing observed counts. A missing or unreadable profile leaves layout in source order. An inaccurate profile can change the layout and cycle count while leaving execution behavior intact.

## Known problems

The signed range analysis loses precision when paths disagree or a nonconstant range may wrap. Store elimination treats all remaining divisions and remainders as potentially trapping. The late jump pass conservatively retains shared fallthroughs based on incoming edges before redirects. Select conversion reads both sources and can wait for an unchosen value. Loop hoisting can add work on inputs that skip the loop. The layout estimate treats branch and cache penalties as additive and cannot account for overlap with register reloads or inaccurate counts. The register reuse guard uses reload counts from one- and two-block cycles as a proxy for timing. [Verification and handoff](docs/WORKFLOW.md)

Summation lowering currently handles only a narrow loop shape, bounds through 255, and degree through three. Finite specialization deliberately rejects memory and functions with more than two relevant parameters and may improve the complete-domain geometric mean while slowing an individual input. Scheduling estimates bounded paths, including spilling contexts; longer control-flow histories can still have different timing. Public samples and generated comparisons provide evidence, not a proof of all existing optimizer passes or unseen-test performance.

Memory reuse is currently limited to affine addresses with source-proven constant coefficients and offsets in a simple one-body loop. Unknown aliases and more complex loop nests reject. The initial preload and carry copies can cost more on short or skipped loops even when the modeled longer paths improve. This pass preserves existing doubling plans but does not jointly search scheduling, reuse and unrolling.

The bit checker is intentionally incomplete: arbitrary nonlinear loops and variable-trip bit operations remain unchanged. Wider finite specialization still rejects memory, so it cannot directly specialize array Adler/CRC functions. Candidate search is capped and trained on a fixed finite corpus; some input timings can regress, even with a misleading profile kept within bounded weights. The nested closed forms cover additive one-body recurrences, not arbitrary loop nests or general aliasing.

Checksum deferral currently requires a common positive constant modulus, a simple one-body loop, bounded nonnegative affected arithmetic and a unique normal exit. Negative/signed checksum recurrences, different moduli, affected addresses/predicates, raw live-out intermediates and possible sign-boundary crossings reject. It does not optimize arbitrary modular exponentiation or split oversized loops into reduction chunks.
