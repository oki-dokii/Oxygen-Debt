| D-006 | Accepted | When the input names more registers than Kiln can hold, preserve copy operands read in multiple blocks. Unrestricted propagation extended temporary lifetimes and increased spill costs on several public samples. This policy recovered those cases at the cost of skipping some profitable copies. | A later pass can estimate register pressure with more precise live ranges. |
| D-007 | Accepted | When spills can cost cycles, avoid retaining cheap expression results across effects. The first implementation kept a temporary live across a load and store in `bubble_sort`, where recomputing an addition was faster. Keep adjacent fusion based on machine features and latency. | A spill-aware cost model can distinguish profitable reuse or fusion more precisely. |
| D-008 | Accepted | Coalesce adjacent pure producers and copies when the temporary is dead and the machine can charge for spills. For a fused multiply-add with a power-of-two factor, consider the machine's shift-add instruction as well. These choices cut register traffic in `spill_storm` and removed the public regressions on `paren_depth`. | Live-range allocation or a wider timing model can account for dependencies introduced by writing an existing register. |
| D-009 | Accepted | Resolve jump-only chains before liveness and keep the original entry and edges into jump cycles. The public matrix showed faster samples with no regressions against the previous revision. | Layout measurements show that redirecting a jump costs more than retaining a hop, or liveness exposes enough jump-only blocks to justify a second pass. |
| D-010 | Accepted | Use profile counts only for layout. Favor existing fallthroughs when counts are close and require a lower estimated branch and cache cost before emitting a new order. All sample behaviors matched, and cycle totals improved on four of five machines. | Timing traces justify a cost estimate that accounts for overlap with register reloads. |
| D-011 | Accepted | Reuse loads and forward stored values within a block using exact address identities. Invalidate dynamic addresses on any store and preserve facts for distinct literals on a literal store. An earlier successful access proves the later load cannot trap. When spills cost more than loads, keep literal-address and self-overwriting loads that would gain a register read. | Trace evidence justifies a more precise alias or spill model. |
| D-012 | Accepted | Reuse the same name pool across blocks for values defined and consumed within a block. Reserve parameter names, values live across edges, and volatile operands. If the candidate still exceeds register capacity, retain original names in short cycles when repeated traversal predicts more reloads. | A timing regression justifies modeling longer paths or readiness dependencies. |
| D-013 | Accepted | Use signed intervals to prove exact nonzero divisors and to reduce division or remainder by powers of two for nonnegative dividends. Discard arithmetic bounds that may wrap. Widen expanding ranges on repeated backward edges and use local facts when the analysis budget runs out. | A benchmark needs more precise branch or arithmetic facts. |
| D-014 | Accepted | Hoist groups of at least two pure instructions that leave one result live through a simple loop. Moving independent address expressions caused spills and broke profitable fusion on several public cases. | A static timing estimate or profile can justify moving more values. |
| D-015 | Accepted | Use address bounds to discard unused loads. Remove an overwritten store only when every reachable continuation from its block is free of possible traps and no read or volatile operation intervenes before the overwrite. This preserves the original store sequence on trapping executions. | Stronger proofs can classify more accesses or continuations as safe. |
| D-016 | Accepted | Invert a branch on a comparison with zero when the tested value still has a register holder. Prefer the register read by the comparison and skip operands read in multiple blocks when spills can cost cycles. This keeps copies from staying live across the branch unnecessarily. | A more precise spill model can test the skipped cases. |
| D-017 | Accepted | Double short loops with a fallthrough from the header to the body. Keep a condition check after each copy and fit the added code in cache when cache misses cost cycles. Moving the check alone slowed some loops on wider machines. Alternating two copies saves a taken back edge every other iteration. | A timing model can test larger bodies, different layouts, or loops with more register pressure. |
| D-018 | Accepted | Carry profile counts across early jump redirects. Revisit jump-only blocks after dead-code removal and layout, preserving shared fallthroughs when bypassing them could add a taken jump. A jump to a return-only block can return directly. | New traces can show whether additional shared chains can be bypassed profitably. |
| D-019 | Accepted | Use exact signed ranges to seed local constant folding. Share the arithmetic evaluator between range analysis and local folding. Send facts only to the selected edge for exact conditions, and revisit the block if its inputs change. | A workload needs better precision at joins or on fused operations. |
| D-020 | Accepted | Convert isolated copy and constant assignment diamonds into a select. An experiment with add/subtract arms was slower than the narrower version on three supplied machines, so retain arithmetic branches. | Block merging or a readiness model can justify broader conversion. |
| D-021 | Accepted | Merge adjacent single-predecessor blocks after allocation and layout. An earlier version merged before allocation and slowed the four-register `branchy_select` case. The late pass removes transfers while preserving the allocated register sequence. | A pressure-aware model can justify simplifying across merged regions earlier. |
| D-022 | Accepted | Lower structurally proven polynomial sums of degree at most three with bounds through 255. Use wrapping symbolic arithmetic and require extra nonnegative, no-overflow proofs for a final modulus. Choose exact inverse-three multiplication when cheaper than division. This reduced default `sum_sq` from 163 to 13 cycles. | Broader induction-variable/range proofs can support more loop shapes without weakening the contract. |
| D-023 | Accepted | Reuse the explicitly permitted organizer interpreter and timing model in `src/kiln.py`, with credit. Specialize pure single-parameter functions only after proving at most ten relevant masked bits. Evaluate the entire quotient domain, reject any trap or timeout, and verify every generated candidate. Use a deterministic two-million-step budget, no names or stored answers. | Compile time or code size grows, or a proof can safely handle more parameters or effects. |
| D-024 | Accepted | Schedule bounded blocks using RAW/WAR/WAW and ordered effect edges. Require no regression on modeled short paths and skip programs that can spill. The initial spilling version slowed four public cases despite passing the local timing guard; the conservative guard removed those regressions. | A model of longer register/cache histories can justify scheduling spilling programs. |
| D-025 | Accepted | Extend scheduling to spilling programs only after checking bounded incoming and outgoing paths and repeated simple cycles. Retain the existing dependency proof and require no modeled context to slow. Limit path fan-out and total timing work deterministically, skipping optional candidates when coverage exceeds those limits. This recovers useful four-register scheduling while rejecting the earlier public regressions. | Longer histories or larger loops show that these bounded timing contexts miss a regression. |
| D-026 | Accepted | Carry proved affine memory values between iterations of a simple counting loop. Use safe literal preloads and preserve every store and potential trap; reject unknown aliases, volatile bodies, added spills and lost loop doubling. An early version slowed `alias_stores` because its extra copy disabled doubling, so the final guard retains existing doubling plans. Structural timing paths choose among safe alternatives; they are not equivalence proofs or guarantees on all trip counts. | Broader loop/alias proofs or joint reuse, allocation and unrolling search can safely extend the pass. |
| D-027 | Accepted | Prove fixed-trip word/bit recurrences and synthesize SWAR counts, reflections and GF(2) maps. Conditional merges require constant per-bit arm differences; no nonlinear arithmetic or effects are guessed from testing. | Broader algebraic proofs can cover unsupported operations without weakening soundness. |
| D-028 | Accepted | Add a bounded nested-loop candidate with dominance-checked invariant motion and repeated additive-loop collapse. Preserve zero-trip state through external-use gates and explicit final counter/condition restoration. | A tested polynomial or memory-aware extension can handle more nests. |
| D-029 | Accepted | Expand pure finite proofs to two parameters and twelve total masked bits, retaining exhaustive coverage and adding a timing-work/output-size cap. Array loads still reject. | Resource measurements justify wider bounds or a separate memory proof. |
| D-030 | Accepted | Keep the unchanged input in a bounded portfolio of pass combinations. Rank with deterministic source-independent cases; profiles only add bounded timing weights. Retain semantic proof requirements, and document four public sample regressions against the previous release. | More representative held-out evidence or a stronger model justifies changing the corpus/portfolio. |
| D-031 | Accepted | Offer deferred common-modulus checksum reductions only with an all-input congruence/interval proof, canonical original live-outs on every exit and already-reduced initial state. Keep loads at untainted addresses, reject body writes/I/O, and refresh ranges after the rewrite. Mathematical positive bounds must not use wrapped constant folding; direct rejection fixtures cover that pitfall, late-tainted live-outs and affected shift counts. | A proof of chunked reductions, signed recurrences, edge splitting or multiple moduli can safely extend the candidate. |
| D-032 | Accepted | Expand only bounded, source-proven constant control paths while retaining every unknown/effect operation in execution order.
