# Development workflow and handoff

Start each session here. Read the [current requirements](SRS.md), [technical plan](TRD.md), and [decision log](DECISIONS.md) before changing the optimizer. Check the Git diff and use the current implementation and tests to verify this handoff.

| Stage | Work | Check before proceeding |
|---|---|---|
| 1. Baseline command | Add `build.sh`, the Python `kopt` entry point, and the permitted kit code it uses. Read the machine and emit the input unchanged. | The documented command works from a clean checkout and from another directory. |
| 2. First passes | Implement local constant folding and copy propagation, then add liveness and dead pure code removal. | Verify a beneficial rewrite and a case where each pass must preserve the original behavior. |
| 3. Batch validation | Compare originals with optimized outputs under the official validator, then measure cycles with the simulator. | Check public workloads across supplied machines, repeated-run determinism, and runtime on a generated large program. |
| 4. Performance work | Add fusion, register reuse, or scheduling in separate changes. | Keep changes with measured benefits. Investigate slower cases and retain a reproducer for failures. |
| 5. Submission | Update the root README and the seven required design sections. Build from a clean checkout and record demo and benchmark evidence. | Review the submission checklist and confirm organizer access before sending the repository link. |

For each change, write down the fact that makes the rewrite safe. Add a small test when the public suite would miss the failure mode. Start with `const_chain`, `junk_dead`, and `common_subexpr` for wins, then run `dead_div_trap`, `sensor_sum`, and `alias_hazard` as guardrails. Include same-input cycle comparisons and record skipped validator inputs separately from passing inputs.

## Current handoff

- **State (2026-11-12)** — Added proved affine memory reuse across a simple counting loop. Fresh registers carry values established by a later load/store into the next iteration. Safe initial reads, alias checks, machine capacity, deterministic budgets and protection of existing loop doubling gate every candidate. This is a narrow extension, not general nested-loop or global alias optimization.
- **Latest evidence** — Forty-four unit tests passed. All 500 public pairs and 32,000 generated comparisons matched, with no original timeouts. Against `a4ab55f`, 11 public pairs improved and 489 tied; none slowed. Totals: default 16,645 → 16,565; few registers unchanged at 31,190; no fused 19,070 → 18,968; slow memory 25,703 → 25,462; wide/fast 16,808 → 16,780. Sum across machines: 109,416 → 108,965. These summed sample totals are not a judging score. Maximum local parallel optimizer wall time: 0.493 seconds.
- **Specific gains** — `stencil3`: default 386 → 324, no fused 449 → 365, slow memory 722 → 499, wide/fast 263 → 242. `conv_mac` and `prefix_sum` also improve on supported machines. Register-capacity guards deliberately retain the four-register outputs. The first experiment slowed `alias_stores` by losing loop doubling; retaining every existing doubling plan removed those regressions.
- **New proof tests** — `tests/rolling.py`: 31 renamed/shuffled cases × eight machines × 24 inputs, checked both directly and through the complete compiler: 11,904 matches. Forty-two pairs actually transform; these include 178 zero-trip checks, eight division traps and 42 bad-address traps. Cases include positive/negative address slopes, strides one/two, load/store suppliers, scratch boundaries, overwritten address registers, unknown aliases and carried locals. Two additional unit tests check affine wrapping and claimed disjointness against independent arithmetic.
- **Other checks** — Stress seeds 60723 and 921730 passed 9,600 comparisons. Existing summation, finite-domain and scheduling suites passed 64,480, 39,136 and 118,784 comparisons. The finite suite separately skips 160 nonterminating references. With 32,000 public generated inputs and 11,904 new direct/integrated comparisons, the local total is 275,904 generated comparisons. The replayable demo passes, including stores before a division trap.
- **Runtime and determinism** — A generated 100,001-instruction case completed in 0.754 seconds locally; finite-budget exhaustion completed in 0.614 seconds. Those cases plus sum_sq, collatz and matmul4 remain deterministic across hash seeds 1 and 87654321. The three memory-reuse workloads on default and wide/fast machines also produced identical bytes, in at most 0.066 seconds, writing only the requested output. These are local measurements, not judging-hardware guarantees.
- **Ubuntu release verification** — Code `6c82e83c18bbc990e53d11abde1e5c9fa747aead` passed on Ubuntu 22.04 x86-64 / Python 3.10.12: build, 44 unit tests, expanded demo, 500 public pairs, 32,000 generated comparisons, 4,800 stress comparisons, and 234,304 targeted comparisons including the new memory suite. Default total was 16,565 cycles, and maximum public optimizer wall time was 0.391 seconds. [Successful run and logs](https://github.com/oki-dokii/Oxygen-Debt/actions/runs/43173656632). The subsequent release commit only records this verification.
- **Limits and next target** — Memory reuse handles constant-coefficient affine addresses in a simple one-body loop, up to 128 body instructions. It skips volatile bodies, unknown aliases and added spills. Fixed preload/copy costs can lose on short or skipped loops, and two/eight-iteration timing paths do not predict every input. The pass does not jointly optimize reuse, allocation, scheduling and unrolling. Next investigate broader loop-nest memory/address transformations or proved bit-operation synthesis. The [public comparison](COMPARISON.md) is pinned to the previous 109,416-cycle revision; the strongest peer's 52,130 remains author-reported and unreproduced.
